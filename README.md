# Domestic Violence KPI Analysis (`DOMV9a`)

A reproducible analysis pipeline, notebook, and dashboard for a UK local-authority
administrative KPI — **Domestic Violence Incidents Level (Medium Risk)** — covering
financial years 2011/2012 through 2018/2019.

This is **not** a decorative EDA notebook. Every result here is either (a) an
explicit statistical test with a reported p-value, or (b) an out-of-sample
validated forecast — see [Key findings](#key-findings) and, in more depth,
`notebooks/01_domestic_violence_kpi_analysis.ipynb`.

> **Scope note.** This project analyses aggregate, de-identified administrative
> statistics only — counts of recorded incidents, with no case-level or personal
> data. It does not, and is not intended to, provide guidance for individuals
> affected by domestic violence. Readers working directly with people experiencing
> domestic abuse should refer to appropriately qualified local support services
> and national helplines.

**Design principle:** `src/` contains all analysis logic and is the single source
of truth. The notebook, the pipeline, and the Streamlit app all call into `src/` —
none of them re-derive statistics independently, so the three can never silently
report different numbers for the same KPI.

## Setup

```bash
git clone <this-repo>
cd domestic-violence-kpi-analysis
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Running the pipeline

The pipeline loads the raw CSV, cleans it, validates it (hard-fails if
cross-granularity reconciliation ever breaks), runs the full statistical
analysis, fits and validates the forecast model, and writes every processed
dataset, figure, model file, and the summary report:

```bash
python -m src.pipeline
```

Expected console output ends with:

```
Model MAE=7.70 vs naive MAE=8.75 (12.0% improvement)
...
Done. Outputs written under: reports, data/processed, models
```

## Running the notebook

```bash
jupyter lab notebooks/01_domestic_violence_kpi_analysis.ipynb
```

The notebook imports `src/` directly — run it from a kernel with the project
root on `sys.path` (the first code cell handles this automatically) so its
cells stay in lockstep with the pipeline. To regenerate the notebook file
itself from `notebooks/build_notebook.py` (e.g. after editing its narrative):

```bash
cd notebooks && python3 build_notebook.py
jupyter nbconvert --to notebook --execute --inplace 01_domestic_violence_kpi_analysis.ipynb
```

## Running the dashboard

The app reads only the **processed** artifacts written by the pipeline — run
the pipeline at least once first:

```bash
python -m src.pipeline
streamlit run app/streamlit_app.py
```

## Key findings

| # | Finding | Evidence |
|---|---|---|
| 1 | The raw export mixes three time granularities (monthly/quarterly/annual) for one KPI in a single table. | `src/data_loader.classify_granularity` |
| 2 | Monthly sums match reported annual totals **exactly** for all 4 complete years (0 discrepancy). | `src/validation.reconcile_monthly_vs_annual` |
| 3 | Incidents rose 278→463→621→715 (2011/12→2014/15); year-on-year growth **decelerated** every year (+66.5%→+34.1%→+15.1%). | `src/analysis.annual_trend_tests`, `yoy_change` |
| 4 | No statistically significant within-year seasonality (ANOVA p≈0.85), despite a visually suggestive winter bump. | `src/analysis.seasonality_anova` |
| 5 | Two distinct, non-interchangeable gap regimes: a declared "Not Collected" interruption (Aug 2015–Mar 2017) and an apparently incomplete later extract (FY2017/18 wholly absent; FY2018/19 present but blank). | `src/validation.data_quality_summary` |
| 6 | A trend+seasonal model, trained on 2011/12–2014/15 and validated on 4 held-out real months, beats a naive-persistence baseline (MAE 7.7 vs 8.75; MAPE 12.4%). | `src/forecasting.validate_on_holdout` |

**Interpretation held throughout:** this KPI measures *recorded* incidents, not
the true prevalence of domestic violence. Rises and falls plausibly reflect
changes in police recording practice, risk-assessment tool rollout, and
awareness/reporting campaigns as much as changes in the underlying rate of
abuse. No causal claim is made anywhere in this project about *why* the trend
moved — see the notebook's Limitations section (§17) for the full list of
caveats.

## Data cleaning decisions

Three problems in the raw export are handled explicitly rather than silently
coerced:

1. **`value` mixes a number and a unit suffix** (`"278.00 Number"`) — extracted
   via regex, not string-splitting, to be resilient to formatting variance.
2. **`value` sometimes literally equals `"NC"`** ("Not Collected") — this is a
   *meaningful missing-data flag*, kept as a separate boolean column
   (`not_collected`) rather than collapsed into an ordinary `NaN`, because it
   tells a different data-quality story (a declared collection gap) than a
   truly blank cell (an incomplete extract).
3. **`period` conflates financial year and reporting granularity** into one
   string (`"2013/2014_Q2"`, `"2013/2014_Nov"`, `"2013/2014"`) — decomposed
   into two explicit columns (`financial_year`, `granularity`) so the three
   granularities can be analysed, and cross-validated against each other,
   separately.

## Visual design system

One color theme (defined once in `config.yaml` → `theme:` and applied via
`src/theme.apply_theme()`) is shared by every chart across the notebook, the
pipeline's saved figures, and the Streamlit app:

| Role | Hex |
|---|---|
| Primary line / headline series | `#1B3A4B` (midnight teal) |
| Secondary series | `#5DA9A1` (muted teal) |
| Alert / risk / outlier accent | `#C1666B` (muted rose) |
| Warning / forecast accent | `#D9A441` (amber) |
| Neutral / baseline | `#8C8C89` (warm grey) |
| Background | `#F7F4EE` (warm paper) |
| Gridlines | `#DDD8CC` |

Saturated "dashboard" reds/greens are deliberately avoided — this is a
sensitive subject and the palette is intended to read as analytical, not
alarmist.

## Limitations (summary — see the notebook for the full discussion)

- Recorded incidents are not a direct measure of true prevalence.
- Single geography, single risk band (medium-risk only).
- Trend inference relies on only 4 complete annual data points; treat the
  precise linear growth rate as indicative, not a reliable extrapolation
  constant (Kendall's tau, the more conservative test, does not reach
  significance at α=0.05 with n=4).
- The forecast model is validated for a 4-month horizon only and is
  deliberately not extrapolated across the known 2015/16–2018/19 reporting
  gaps.
- No confounding/control variables (population, funding, policy changes) are
  available in this dataset, so no causal explanation for the trend is
  possible from this data alone.
